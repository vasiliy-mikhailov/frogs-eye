Three Hostnames, One Request

LiteLLM is what answers at inference.mikhailov.tech, and meterproxy stays in front of it — because LiteLLM can price a request but cannot measure how fast the box served it. Everything reaches the engines by public hostname, so a second GPU joins the fleet by DNS record.

Binding meterproxy — two environment variables, no code change

ROUTES        {"/qwen-3.8-27b-nvfp4": "litellm:4000", "/paddleocr-vl-1.6": "litellm:4000"}
UPSTREAM_KEY  ""          # was the engine key. Empty = pass the consumer's key through.
CLIENT_KEYS   unchanged     # still the label table: sk-bumpjava-… → "bump-java"

Emptying UPSTREAM_KEY is the load-bearing change. The existing code only rewrites the header when a key is set — if label and UPSTREAM_KEY — so clearing it makes meterproxy forward the consumer's own token to LiteLLM, which is exactly what LiteLLM needs in order to recognise the virtual key. The labelling path is untouched, so every existing Grafana panel keeps its series names.

One free win falls out of this ordering. meterproxy already injects stream_options.include_usage and strips the extra usage chunk back out before the client sees it. Sitting in front, it does that stripping on LiteLLM's behalf — which neutralises the one behavioural risk the research flagged, where LiteLLM can leak a trailing choices:[] frame to fleets that never asked for it.

Decide before building

inference1, inference2 and langfuse do not resolve

No A record, no CNAME on any of the three. Caddy needs the name to resolve before it can obtain a certificate, so this gates everything downstream. inference1 → 77.37.246.197 is the one to create first.

The internet hop runs over WiFi

The host sits behind NAT at 192.168.0.2 on wlo1; the wired eno2 is unplugged. Every 234 KB prompt body crosses the air twice via router hairpin. Plugging in the cable removes the question entirely.

Publishing the engine widens exposure

Today inference-vllm has no published ports and the internet cannot reach it. A public inference1 makes the engine's single shared key the only thing in front of the GPU. Rotate it so only LiteLLM holds it.

What is a token worth here?

Self-hosted means there is no bill to reproduce, so the rate card is a choice. Two useful answers: what the same traffic would cost on a commercial API, and the amortised cost of GPU time. They answer different questions and both can be recorded.
